### 使用规则：每次复制一个完整角色提示词

1. **模板制度与项目业务分开**：本清单保留 M01—M12、工单退回补充闭环、19 项 AI 能力及 I0—I6 的业务练习。版本、阈值、任务数量与技术方案须对照当前 SRS/人工批准核实；原清单中的数字和示例不自动成为新需求，缺失项记录 Q/AS，不编造裁决。
2. **每人完成个人闭环**：读取规则与任务 → 确认范围/稳定功能 → 建立个人分支与 worktree → claim 路径/资源 → 分析实现 → 自检与回归 → 显式提交 → 本人 freeze → 评审/交接/复测 → 人工验收 → 归档。不要以多人分工省略个人自测、冻结或确认。
3. **占位符先解析**：`{USER}` 是真实稳定人员标识，`{SESSION}` 是当前会话唯一标识，`{ROLE}` 每次只取一个角色，`{TASK}` 来自已授权任务，`{SEQ}` 是本会话内协调分配的单据序号。五项身份为 user_id、actor_id、role_id、task_id、lane_id；role_id 不是写锁。已知身份直接沿用，不虚构真人身份或重复追问。
4. **路径写法**：静态参考文件采用目录内有序编号，实际项目工件不添加日期或时间前缀；按任务、角色、人员、会话和单据序号确定唯一名称，时间写入正文。范围表达式 `01~05`、`**`、`{BE,FE}` 等仅表示需解析的工件集合，不能作为字面文件名或传给 claim。输入须从任务/HO 中取已登记的完整路径、冻结号/revision/提交 SHA；不能凭“最新文件”猜版本。新输出在领取前确定具体路径并登记；后续引用沿用该路径，不另起同义文件名重复生成。
5. **固定模板入口**：下表中的文件已存在于团队模板，复制后可作为项目控制入口；冻结后修改仍须 CR。其他业务设计、验收与交付路径是计划产出，不宣称已经存在；示意名称须按任务登记解析为具体路径。CONVENTIONS 及 SPEC-01—05 是项目专用规范；缺少时由 AR 核对来源、建稿并评审，不能假定通用 AGENTS 含企业专用第 11 章。
6. **不可自批**：冻结交付 FROZEN 不等于功能 STABLE；只有真实独立评审、必要测试、业务与人工验收满足后才可标稳。冻结工件的签收、答复、复测及评审另建新单据引用，不能在他人冻结文件中回写。真人批准后可由其他角色/用户接手，原作者也不能自行解冻。
7. **合并与发布单独处理**：源码自测通过不等于候选合并通过；候选完整树验证后才受控集成，main 合并、推送及生产发布按实际版本授权。不得预填“通过”、伪造 QA/业务签字或把文档校验作为业务测试结果。
