# RISKS.md —— 项目风险登记与跟踪册

> **拥有角色**：`PM`。预置大型多角色 AI 协同研发项目的 10 项高频共性风险，项目启动后结合实际业务持续更新。

| 风险编号 | 风险类别    | 风险描述                                                       | 可能性 | 影响程度 | 应对与预防措施                                                                 | 责任角色  | 当前状态 |
| -------- | ----------- | -------------------------------------------------------------- | ------ | -------- | ------------------------------------------------------------------------------ | --------- | -------- |
| `RSK-01` | 需求与范围  | 原始需求存在模糊表述或隐藏假设，导致开发期频繁返工             | 高     | 高       | P1 阶段强制汇总 PO/BE/FE/QA/OPS 五方通读问题至 `01-需求澄清与假设.md` 并闭环   | `PO`      | 监控中   |
| `RSK-02` | 契约漂移    | 前后端对接口路径、字段、枚举或错误码理解不一致                 | 高     | 高       | 严格执行 P3 契约冻结门禁；冻结后破坏性修改必须走 `CR` 变更单                   | `BE`/`FE` | 监控中   |
| `RSK-03` | 角色越界    | AI 会话在修复问题时顺手越权修改其它角色的文档或代码            | 中     | 高       | 单会话单角色；`OWNERS.md` 强约束；收尾必跑 `validate_project.py` 与 `AR` 评审  | `AR`      | 监控中   |
| `RSK-04` | 上下文截断  | 大模型单次生成长文档或大模块代码时发生遗漏或截断               | 高     | 中       | 采用“总纲索引先行 + 分模块分会话生成”；单子任务控制在 1–2 会话内完成           | 全体      | 监控中   |
| `RSK-05` | 状态机漏洞  | 核心业务流转（如退回补充、多级会签、并发提交）出现死锁或脏状态 | 中     | 极高     | P1 建立无空洞状态×事件矩阵；P3 专项设计乐观锁与幂等；QA 100% 覆盖合法/非法转换 | `AR`/`QA` | 监控中   |
| `RSK-06` | 自测自放行  | 开发人员自测通过即视为完成，隐藏越权、边界与集成缺陷           | 中     | 高       | 强制 OPS 独立部署 `test` 环境、QA 独立测试与复测关闭缺陷、PO 殿后验收          | `QA`      | 监控中   |
| `RSK-07` | 环境不一致  | 本地开发环境与测试/生产环境配置、数据库或信创架构不一致        | 中     | 高       | OPS 在 I0 建立统一容器编排与 `.env.example`，全环境同源镜像晋级                | `OPS`     | 监控中   |
| `RSK-08` | 密钥泄露    | 数据库口令、JWT 密钥或大模型 API Key 被误提交进代码库          | 低     | 极高     | `.gitignore` 拦截 `.env`；CI 增加密钥扫描；OPS 上线前执行 `/ready` 安全核查    | `OPS`     | 监控中   |
| `RSK-09` | AI 幻觉风险 | 业务系统集成的 AI 辅助功能输出格式错误、越权或慢响应拖垮主服务 | 中     | 高       | AI 结果仅作建议不直接改状态；统一脱敏、Schema 校验、超时熔断与规则兜底降级     | `AI`/`AR` | 监控中   |
| `RSK-10` | 发布回滚难  | 数据库迁移脚本不向后兼容或未演练回滚，生产故障无法快速恢复     | 低     | 极高     | 迁移遵循“先扩后缩”；P6 必须在 `staging` 完成回滚演练与备份恢复演练并记录耗时   | `OPS`     | 监控中   |

## 个人责任与冻结关联

- 发起 user_id / actor_id / role_id / task_id / lane_id：待填。
- 原工件冻结号、revision、精确提交 SHA、路径：待填。
- 指定接手 user / actor / role / task（可不同于原角色）：待填。
- 实际输出文件必须带唯一任务/单据编号与人员标识；多人编号不得碰撞。
- 已冻结单据的答复、签字与评审用新记录引用原编号，禁止直接回写。
