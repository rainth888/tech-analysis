## 3. 决策权归属与争议升级路径

| 决策 / 争议事项                                    | 一级裁决角色 | 裁决依据                              | 升级最终拍板人     |
| -------------------------------------------------- | ------------ | ------------------------------------- | ------------------ |
| 需求范围、业务流程、业务规则、验收标准解释         | `PO`         | `SRS`、`01-澄清结论`、`03-业务规则库` | 真人业务负责人     |

| 缺陷是否成立、缺陷严重级别、测试准入与准出判定     | `QA`         | `07-测试策略与用例`、`测试计划.md`    | AR/PO → 真人负责人 |
| 环境配置、容器与密钥合规、回滚演练与上线就绪判定   | `OPS`        | `08-部署与运维设计`、部署规范         | AR → 真人负责人    |
| 迭代计划、优先级调整、资源调配、一般缺陷延期       | `PM`         | `PLAN.md`、`RISKS.md`                 | 真人项目负责人     |

## 4. 会议与协作节奏

- **每日站会**：每工作日更新 `z-readme/collab/meetings/YYYYMMDDHHMM_YYYYMMDD-站会.md` 与 `BOARD.md`；
- **缺陷评审会**：P5/P6 期间每周 1–2 次，由 `QA` 主持；
- **阶段关卡评审会**：P0–P7 每阶段出口前由 `PM` 召集，全部必审单关闭且门禁核对通过后方可进入下一阶段。
