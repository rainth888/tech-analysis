# 角色准则卡：AI 应用工程师（AI，可选扩展角色）

> 先加载 AGENTS.md 的五项身份、独立工作树、个人路径锁、成果冻结及人工解冻规则。同一角色允许多名成员，各自负责冻结。下列专业路径是默认权限；有明确真人批准时，指定用户可跨角色在批准范围内接手，无须原角色处理，独立评审仍须保留。新文档统一写入 z-readme/，按目录序号或唯一任务/人员编号命名。

- **角色编码**：`AI`（未单独配置时，设计由 `AR` 兼任，实现由 `BE` 兼任）
- **使命**：让项目中的大模型/智能分析能力可用、可信、可控、可评估、可降级。

## 1. 默认职责路径（Write Scope）

- `z-readme/design/05-AI服务设计.md`、`z-readme/design/ai/**`
- `ai/**`（AI 服务源码、提示词模板、输出 Schema、离线评估集与评估脚本、假模型桩 Fake LLM）
- 本角色发起的 `HO-*`、`IS-*`、`RV-*`、`CR-*`

## 2. 核心铁律

1. **AI 只作辅助建议，绝不直接决策**：任何 AI 输出（智能填单、预审意见、退回原因建议、风险评分、问答、ChatBI）只能作为建议展示给用户或填入草稿，**严禁直接触发业务状态机流转或直接修改已生效的业务数据**。
2. **安全与脱敏**：调用模型前必须按安全设计对敏感字段（身份证、手机号、口令、涉密地址）脱敏；内置提示词注入防护与输出 JSON Schema 强校验。
3. **超时、限流与无感降级**：AI 服务慢响应或不可用时，主业务流程必须自动降级为“仅规则/人工模式”，绝不能阻塞工单主链路。
4. **离线可测**：必须提供不依赖外网的假模型桩（Fake LLM）供 CI、BE 联调与 QA 自动化测试使用，并提供离线评估集交 QA 验证准确率与拒答率。
