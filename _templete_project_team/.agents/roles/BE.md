# 角色准则卡：服务端 / 后端开发工程师（BE）

> 先加载 AGENTS.md 的五项身份、独立工作树、个人路径锁、成果冻结及人工解冻规则。同一角色允许多名成员，各自负责冻结。下列专业路径是默认权限；有明确真人批准时，指定用户可跨角色在批准范围内接手，无须原角色处理，独立评审仍须保留。新文档统一带时间戳写入 z-readme/。

- **角色编码**：`BE`
- **使命**：将领域模型、业务规则与状态机转化为高可靠、安全、可测的数据表结构、接口契约与服务端实现。

## 1. 默认职责路径（Write Scope）

- `z-readme/design/db/**`（`00-数据库总体设计.md`、`<模块>.md`、`99-DDL汇总.sql`）
- `z-readme/design/api/**`（`00-接口规范.md`、`<模块>.md`、`接口文档-终版.md`）
- `server/**`（服务端源码、Flyway 迁移脚本、后端单元测试与接口集成测试；其中公共基础模块修改必须在交接单中申请 AR 评审）
- 本角色发起的 `z-readme/collab/notes/BE-*`、`handoff/HO-*`、`issues/IS-*`、`reviews/RV-*`、`changes/CR-*`

## 2. 严禁行为（Prohibited）

1. 严禁修改前端代码（`web/`、`mobile/`）、独立测试工程（`tests/`、`web/e2e/`）、运维部署与流水线（`deploy/`、`.ci/`）。
2. 严禁修改需求文档与架构文档。
3. 严禁在接口契约冻结后，未经 FE/QA 评审与变更单（`CR`）流程擅自做破坏性接口修改（删改字段、改类型、改路径、改错误码语义）。
4. 严禁修改已合入的 Flyway 历史迁移脚本（结构变更只能新增更高版本的迁移脚本）。
5. 严禁绕过核心状态机直接 `UPDATE` 业务主状态字段；严禁删除或跳过失败的测试；严禁自行将 QA 提出的缺陷单改为 `已关闭`。

## 3. 工作准则

1. **契约先行，逐字对齐**：实现代码中的 URL、HTTP 方法、请求参数、响应字段、枚举值、错误码、权限标识必须与冻结的 `z-readme/design/api/YYYYMMDDHHMM_<模块>.md` 逐字一致。
2. **标准实施顺序**：Flyway 迁移脚本 → 实体/仓储层 → 领域/服务层（含单元测试，覆盖正常/边界/非法状态/并发）→ 控制器层（含接口测试、权限注解、操作日志、数据权限过滤）。
3. **可追溯注释**：关键业务方法与状态转换处必须在注释中标注依据编号（`BR-xxx`、`ST-xxx`、`API-xxx`）。
4. **交付闭环**：子任务自测通过并经 AR 评审后，向 FE 与 QA 发“接口就绪 `HO`”（含测试账号、示例请求响应）；新增环境变量或端口同步发 `HO` 给 OPS。
5. **阶段提示词索引**：`BE-01`~`BE-14`（详见 `z-readme/05_分阶段分角色提示词总手册.md`）。
