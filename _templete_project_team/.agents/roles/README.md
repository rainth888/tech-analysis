# `.agents/roles/` —— 工具无关的岗位角色准则卡

> 先加载 AGENTS.md 的五项身份、独立工作树、个人路径锁、成果冻结及人工解冻规则。同一角色允许多名成员，各自负责冻结。下列专业路径是默认权限；有明确真人批准时，指定用户可跨角色在批准范围内接手，无须原角色处理，独立评审仍须保留。新文档统一写入 z-readme/，按目录序号或唯一任务/人员编号命名。

本目录存放团队项目的 **8 张主角色准则卡** 与 **4 张只读评审/核对员卡**，采用纯 Markdown 编写，不绑定任何特定 IDE、CLI 或大模型厂商。

## 如何在不同 AI 开发工具中加载角色卡

| AI 开发工具 / 环境              | 加载本目录角色卡与 `AGENTS.md` 的标准方式                                                                   |
| ------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| **Cursor**                      | `AGENTS.md` 自动读取；在会话首句引用 `@.agents/roles/<ROLE>.md` 或复制 `.cursor/rules/` 下的对应 `.mdc`     |
| **Codex CLI / Claude Code**     | 根目录 `AGENTS.md` 自动生效；启动会话后第一句指令：“扮演 `.agents/roles/<ROLE>.md` 中的角色并执行 `/inbox`” |
| **Qoder / Windsurf / Cline**    | 在自定义 Rules / System Prompt 中关联 `AGENTS.md` 与当前岗位 `.agents/roles/<ROLE>.md`                      |
| **Antigravity**                 | 根目录 `AGENTS.md` 自动作为 Workspace Rule 注入；在对话首句声明角色并加载 `.agents/roles/<ROLE>.md`         |
| **OpenCode / Aider / 其它 CLI** | 将 `.agents/roles/<ROLE>.md` 映射或复制为对应工具的 agent/profile 文件，或在开场提示词中直接读取            |
| **网页端对话大模型（通用）**    | 将 `AGENTS.md` + `.agents/roles/<ROLE>.md` + 当前任务关联文档作为上下文上传，发送通用开场提示词             |
