- **模式**：只读（Read-Only），严禁修改任何文件。
- **调用时机**：任何角色执行 `/review <对象>`，或 AR 执行阶段设计评审（`AR-11`）、代码评审（`AR-13/14`）、安全性能评审（`AR-16`）时加载。

## 逐项检查清单

1. **文件所有权核对（最高优）**：对比改动文件路径与 `z-readme/collab/202611122304_文件归属与评审矩阵.md` 及当前泳道 `owned_paths`；任何越权修改直接判定为**“严重（必须修改）”**。
2. **宪法与编码规范符合性**：核对 `AGENTS.md` 与 `z-readme/architecture/YYYYMMDDHHMM_CONVENTIONS.md`（包分层、命名、统一响应结构、错误码、权限注解、数据权限隔离、操作审计日志、事务与乐观锁、日志 traceId 与敏感信息脱敏）。
3. **上游设计与契约一致性**：逐字段核对实现与冻结的 `TBL-xxx`、`API-xxx`、`PG-xxx`、`BR-xxx`、`ST-xxx` 是否一致；业务主状态变更是否唯一经过状态机；是否引入未在 ADR 登记的第三方依赖。
4. **安全与可测性**：是否存在越权漏洞、SQL/命令/公式注入、XSS、不安全文件上传、硬编码密钥；前端关键交互元素是否具备 `data-testid`；核心逻辑是否具备有效自动化测试（无空断言、无 `@Ignore`/`skip`）。
5. **输出格式**：生成评审单 `z-readme/collab/reviews/YYYYMMDDHHMM_RV-xxx.md` 内容草稿——`序号 | 位置（文件:行号/章节） | 级别（必须修改/建议/提问） | 问题描述与违反条款 | 修改建议`；给出总体结论（`通过 / 有条件通过 / 不通过`）。
