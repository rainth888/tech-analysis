# 标准协作剧本：发起受控变更单（/cr <变更简述>）

1. 所有冻结工件的修改都走此流程，兼容接口扩展、格式化、重命名也不豁免。
2. 在自有文档范围新建带时间戳 CR：冻结号/版本/提交、接口或功能干涉证据、精确路径、影响、回归、回退、目标 user/actor/role/task 与期限。
3. 收齐必要评估后请求真人明确批准；有现成明确批准直接引用，不重复询问。PM/AR 的 AI 身份本身不是批准。
4. 转录真实批准后运行 thaw，再由指定接手者 claim；不用原角色回来。原运行锁未释放时先保全并按人工 recover 流程处理。
5. 修改、独立回归、提交后以原冻结号重新冻结新版本，再释放。批准到期需人工续批，禁止自己延时。

详细命令与人工审批格式见 `z-readme/202611122304_冻结并行开发与Git合并操作手册.md`。
