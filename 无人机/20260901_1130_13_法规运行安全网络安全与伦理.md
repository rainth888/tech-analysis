# 法规、运行安全、网络安全与伦理

> 提醒：法规、平台规则和标准会变化。本章依据 2026-09-01 可访问的中国政府网、中国民航局等官方页面整理，只作为研发入门导航，不构成法律意见。每次实际飞行和产品发布前必须重新核验适用地区的最新正式文本。

## 一、中国大陆研发者的合规入口

### 1.1 基础行政法规

《无人驾驶航空器飞行管理暂行条例》自 2024-01-01 起施行，规定了无人驾驶航空器分类、实名登记、空域、飞行活动、操控人员、运行识别等框架。应以[中国政府网正式页面](https://www.gov.cn/zhengce/content/202306/content_6888799.htm)为入口阅读全文。

### 1.2 UOM 平台

中国民航局公告的民用无人驾驶航空器综合管理平台入口为 [https://uom.caac.gov.cn/](https://uom.caac.gov.cn/)。所有人、航空器、人员、空域和飞行活动的具体要求需按平台与现行规则办理。

### 1.3 运行识别

中国民航局公布的强制性国家标准《民用无人驾驶航空器系统运行识别规范》GB 46750—2025 于 2026-05-01 实施。民航局 2026 年公告进一步说明网络式运行识别接收与发送安排。研发时应把广播式/网络式运行识别、身份、时间、网络中断和隐私纳入系统架构，而不是发布前临时外挂。

官方入口：

- [GB 46750—2025 标准信息页](https://www.caac.gov.cn/XXGK/XXGK/BZGF/BZGF_GJBZ/202601/t20260120_229783.html)
- [民航局关于网络式运行识别有关事项的公告](https://www.caac.gov.cn/XXGK/XXGK/TZTG/202603/t20260306_230233.html)

### 1.4 其他规则

还需按机型、重量、用途和运行方式核查《民用无人驾驶航空器运行安全管理规则》、适航、运营合格、操控员、空域/飞行活动、无线电、测绘、数据和地方规定。室内测试与室外飞行的法律适用不同，也不意味着室内可忽略消防、人身和场所安全。

## 二、把合规转为技术需求

| 合规主题       | 技术/流程映射                             |
| :------------- | :---------------------------------------- |
| 实名登记与身份 | 序列号、登记标志、生产追溯、设备身份      |
| 空域与飞行活动 | 地理数据、任务校验、审批信息、时间有效性  |
| 运行识别       | 广播/网络消息、定位、时间、网络失败与日志 |
| 操控员与运营   | 账号角色、权限、训练、运行记录            |
| 无线电         | 频段、功率、带宽、型号核准、区域配置      |
| 适航/安全      | 需求、配置管理、验证、故障和持续适航      |
| 隐私与数据     | 最小采集、告知授权、加密、保留和删除      |

合规需求应可测试，例如验证运行识别在网络中断、GNSS 不可信和设备重启时的状态，而不是只检查界面上有一个开关。

## 三、运行风险管理

### 3.1 风险要素

飞行器动能、最大尺寸、运行高度/速度、地面人员密度、关键基础设施、空中交通、环境、操作者能力、链路和自主程度。相同无人机在封闭试验场与城市人群上空的风险完全不同。

### 3.2 分层控制

1. 消除：能否用仿真、地面机器人或固定传感器完成？
2. 替代：用更轻、低能量、带桨保护的平台。
3. 工程：冗余、地理围栏、限高限速、降落伞（需验证自身风险）、急停。
4. 管理：场地、人员隔离、检查表、气象和应急。
5. 个体防护：只作为最后一层，不能替代前述措施。

## 四、网络安全架构

### 4.1 资产与威胁

资产包括控制权、固件、密钥、位置、图像、任务、账号和日志。威胁包括未授权控制、命令重放、恶意固件、参数篡改、云账号接管、依赖漏洞、供应链植入和隐私泄露。

### 4.2 基本控制

- 每设备唯一身份，不使用全产品共用默认密钥。
- 安全启动、签名升级、版本/硬件兼容和回滚保护。
- 链路双向认证、最小权限、命令新鲜度和审计。
- 敏感数据传输/存储加密，密钥与普通配置分离。
- 调试接口量产锁定但保留受控恢复流程。
- 云端 API 限速、授权、日志和异常检测。
- SBOM、漏洞监测、补丁、停止支持和事件响应。

### 4.3 安全不能破坏飞行安全

鉴权服务超时不能阻塞姿态控制；证书过期不能导致空中突然停机；日志加密不能耗尽实时资源；安全更新失败必须可回滚到可信镜像。

## 五、MAVLink 和地面站安全

使用 MAVLink 2 签名时妥善管理密钥、链路 ID 和时间；仍应在不可信网络上使用加密隧道/隔离。地面站导入任务、参数和固件前验证来源、范围和机型。USB、SD 卡和日志解析器也属于攻击面。

## 六、GNSS 与传感器可信性

系统应通过多源一致性、信号质量、惯导预测和地理/运动约束识别异常，不把单一 GNSS 状态当绝对可信。禁止研发和测试主动干扰/欺骗公共无线电与导航系统；相关鲁棒性研究应在合法屏蔽、仿真或经批准设施中完成。

## 七、隐私和数据伦理

- 只采集完成任务必要的数据和分辨率。
- 对人员、车辆、住宅等建立告知、授权和最小化策略。
- 明确保留周期、访问角色、导出和删除机制。
- 训练数据去标识化并记录许可和来源。
- AI 模型评估不同地区、人群、天气和场景的偏差。
- 不以“公共场所”作为无限采集和长期留存的理由。

## 八、开源与第三方内容合规

维护依赖名称、版本、来源、许可证、修改、分发义务和版权声明。地图、字体、视频编解码、AI 模型和训练数据也有各自许可。不要从未知网盘下载商业书籍、固件或模型后放入产品。

## 九、负责任披露与事件响应

发现漏洞时保留证据，联系维护者/厂商安全渠道，给出合理修复窗口，避免公开可直接危害在役设备的细节。产品方应具备设备识别、影响范围、缓解、修复发布、用户通知和事后复盘能力。

## 十、研发禁止项

- 武器化、攻击载荷或伤害性自主决策。
- 绕过地理/运行识别/登记等监管以实施违规飞行。
- 未经授权访问、接管或干扰他人无人机、GNSS、遥控、图传和网络。
- 在人员密集区或敏感设施进行未经批准的故障/极限试验。
- 使用未经许可的数据集、地图、模型或商业电子书。

## 十一、项目合规检查表

1. 机型、重量、用途、地区和运行方式已确定。
2. 适用法规、标准、登记、人员、空域和审批有正式来源。
3. 无线频率、发射设备和区域配置满足要求。
4. 运行识别已进入架构、接口和故障测试。
5. 固件、参数、密钥和设备身份有安全生命周期。
6. 图像/位置/日志有隐私、授权、保留和删除规则。
7. 开源、模型、数据和编解码许可已审查。
8. 有事故/漏洞报告、隔离、修复和用户通知流程。
