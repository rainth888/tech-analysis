# 嵌入式软件、实时系统、总线与驱动

## 一、飞控软件为什么不同于普通嵌入式应用

普通应用卡顿可能只是体验下降；飞控控制周期抖动、传感器时间戳错误或高优先级死锁可能立即改变闭环稳定性。飞控软件需要在资源有限条件下提供确定性、故障隔离、可观测性和可恢复升级。

## 二、语言与工具基础

### 2.1 C/C++

必须理解对象生命周期、静态/栈/堆、对齐、整数溢出、浮点、volatile 的边界、原子操作、未定义行为、编译优化和链接脚本。C++ 可提供 RAII、模板和类型安全，但动态分配、异常、隐式拷贝和复杂运行时特性要按实时约束管理。

### 2.2 Python 与脚本

Python 适合日志分析、参数扫描、仿真编排、代码生成和地面工具，不适合未经实时设计直接承担基础姿态闭环。脚本也必须有依赖锁定、输入验证和可复现输出。

### 2.3 工具链

- Git：版本、分支、代码评审、可追溯标签。
- CMake/Make/Ninja：构建目标和依赖。
- GCC/Clang：警告、静态分析、sanitizer（主机测试）。
- GDB/OpenOCD/SWD：断点、回溯、寄存器和内存。
- CI：单元测试、SITL 回归、格式、静态分析和产物留存。

## 三、裸机、RTOS 和操作系统

| 平台          | 适合               | 主要优点                      | 主要限制                     |
| :------------ | :----------------- | :---------------------------- | :--------------------------- |
| 裸机/超级循环 | 极简 IO/安全 MCU   | 启动快、路径清楚              | 复杂并发和扩展困难           |
| FreeRTOS      | 通用 MCU 实时任务  | 小、生态广                    | 文件/网络/POSIX 需组合       |
| NuttX         | 完整飞控 MCU       | POSIX 风格、驱动/文件系统丰富 | 配置和移植复杂度更高         |
| Zephyr        | 网络化嵌入式节点   | 现代配置、驱动和协议生态      | 飞控项目集成需评估           |
| Linux         | 伴随计算和地面系统 | 驱动、网络、视觉生态丰富      | 默认非硬实时、启动和故障面大 |

PX4 常用 NuttX；ArduPilot 有自己的实时抽象并支持多种板级环境；Betaflight 更接近面向高频控制的 MCU 固件。学习时先理解其调度模型，不要仅比较“用了哪个 RTOS”。

## 四、实时调度

### 4.1 任务分类

- 硬截止：错过可能直接破坏控制或执行器更新。
- 软截止：偶发错过会降级但可恢复，例如部分遥测/日志。
- 后台：参数保存、媒体整理等，可受限执行。

### 4.2 频率不是唯一指标

需要同时测量：周期、执行时间、最坏执行时间、启动相位、抖动、排队时间和截止期违例。平均 CPU 30% 仍可能因瞬时锁、cache miss、Flash 擦除或 SD 卡阻塞导致控制超时。

### 4.3 优先级设计

优先保障传感器数据就绪、估计、角速度控制和执行器输出；日志、地面传输和复杂任务不能反向阻塞。共享资源要考虑优先级反转，使用优先级继承、无锁队列或复制策略时都需验证边界。

## 五、中断、DMA、Cache 与内存

### 5.1 中断

ISR 应短小：确认来源、捕获时间、搬运最少状态并唤醒任务。不要在中断里进行不确定长度解析、日志格式化或阻塞操作。记录中断超时、丢样和嵌套统计。

### 5.2 DMA

DMA 降低 CPU 搬运，但引入缓冲区所有权、完成时序和 cache 一致性问题。双缓冲/环形缓冲应明确生产者、消费者、写指针、读指针和溢出策略。

### 5.3 Cache

带 D-cache 的 MCU 上，CPU 和 DMA 可能看到不同内容。需要正确的 cache clean/invalidate、对齐和内存区域属性。偶发“传感器数据损坏”可能不是传感器，而是缓存维护错误。

### 5.4 动态内存

飞行关键路径通常避免不可控动态分配。若使用内存池或动态对象，要证明上限、碎片、失败处理和并发安全。栈大小通过水位和最坏调用链验证，不凭经验设置。

## 六、驱动设计

### 6.1 驱动不只是读寄存器

一个合格传感器驱动至少包括：

- 探测、复位、器件 ID 和版本检查。
- 配置写入与读回验证。
- 数据就绪、突发读取、FIFO 和溢出处理。
- 精确采样时间戳或延迟补偿。
- 原始值到 SI 单位转换、量程和饱和标志。
- 总线超时、CRC/帧错误、重试上限和恢复。
- 温度、错误计数、采样率和延迟统计。
- 自检、健康状态和热插拔/重启边界。

### 6.2 SPI

明确模式、最大时钟、片选时序、寄存器地址位、dummy byte 和读写长度。多个设备共享总线时，保证配置切换原子性，核算最坏总线占用，并避免低优先级长事务阻塞 IMU。

### 6.3 I²C

核算上拉和总线电容，处理 SDA 被拉低、时钟拉伸、仲裁和总线恢复。飞行关键高频 IMU 通常更偏向独立 SPI，以降低地址冲突和总线锁死影响。

### 6.4 UART

处理 DMA 环形缓冲、空闲线、部分帧、丢字节、校验、波特率误差和重新同步。GNSS 接收时间与消息内部测量时间不同，不能直接把 UART 到达时刻当定位时刻。

### 6.5 CAN/Cyphal

需要设计节点身份、消息优先级、带宽预算、超时、重复节点、总线关闭恢复和终端电阻。分布式执行器还需全网时间同步和失联后的本地安全行为。

## 七、消息中间件和数据契约

### 7.1 发布订阅

PX4 uORB、ROS 2 topic 等将生产者和消费者解耦，但必须定义队列深度、可靠性、历史策略、更新率和过期规则。高频 IMU 与低频状态不应使用相同 QoS 思维。

### 7.2 每条数据至少应说明

| 字段              | 目的                         |
| :---------------- | :--------------------------- |
| timestamp_sample  | 物理量实际采样时间           |
| timestamp_publish | 软件发布/传输时间            |
| frame_id          | 坐标系或传感器身份           |
| units             | SI 单位及缩放                |
| variance/quality  | 不确定度或质量               |
| sequence          | 检测丢样和乱序               |
| status            | 饱和、自检、超时、重置等状态 |

### 7.3 参数系统

参数需要类型、范围、单位、默认值、重启要求、版本迁移和依赖检查。参数不是绕过代码评审的任意变量；会改变安全行为的参数应受权限、审计和一致性保护。

## 八、时间同步

### 8.1 时间来源

- MCU 单调时钟：用于调度和相对时间。
- GNSS PPS/时间消息：提供高精度绝对时间参考。
- 相机触发/帧同步：对视觉惯性融合关键。
- MAVLink TIMESYNC、PTP、ROS 2 时间：跨设备对齐。

### 8.2 常见错误

系统时间因 NTP 跳变；32 位计数器回绕；驱动以读取结束时间标记 FIFO 全部样本；相机以接收帧时间代替曝光中点；伴随计算重启后时间基准改变。

### 8.3 验证方法

使用 GPIO 翻转、逻辑分析仪、PPS、硬件触发和日志交叉相关，测量完整链路延迟及分布，而不是只看软件打印的两个时间戳。

## 九、启动、升级与恢复

### 9.1 启动链

ROM→Bootloader→镜像校验→板级初始化→驱动→估计器→控制→通信→解锁就绪。每一步都要有超时、错误码和安全输出默认值。

### 9.2 OTA/固件升级

- 镜像签名与完整性校验。
- 硬件/板型/版本兼容检查。
- A/B 或可靠回滚方案。
- 断电、空间不足、损坏包和重复升级测试。
- 参数迁移和降级限制。
- 恢复模式不允许意外使能执行器。

### 9.3 安全启动

安全启动建立从不可变根到应用镜像的信任链。密钥生成、注入、备份、轮换、撤销和生产权限比“支持某加密算法”更重要。

## 十、日志和可观测性

日志应包含固件/参数/硬件版本、启动原因、重置计数、传感器状态、估计创新、控制设定与输出、饱和、模式和 Failsafe 事件。日志本身不能阻塞实时任务；存储满、SD 慢或文件损坏要可检测并降级。

事件日志适合记录状态变化，连续日志适合波形分析，统计计数适合发现偶发错误。三者都需要统一时间基准。

## 十一、编码与评审规则

- 明确单位和坐标系，优先使用类型/命名表达。
- 所有外部输入做范围、长度、状态和新鲜度检查。
- 浮点 NaN/Inf、除零、归一化零向量都有处理。
- 状态机穷举非法转移，安全输出有唯一所有者。
- 不在关键路径使用无界循环、无界重试和不可控阻塞。
- 编译警告视为错误；运行静态分析、单元和回放测试。
- 变更必须说明对周期、内存、日志、参数和兼容性的影响。

## 十二、本章实践与验收

1. 为 IMU→估计→控制→执行器链建立任务频率、最坏时间和优先级表。
2. 写一个环形缓冲并测试溢出、乱序、消费者变慢和计数器回绕。
3. 模拟 SPI 超时、传感器重启和异常 ID，验证驱动有限重试和健康上报。
4. 用 GPIO/逻辑分析方法测量“数据就绪→执行器更新”的延迟分布。
5. 为升级设计断电测试矩阵，证明旧镜像可恢复。
