## 一、这套知识库解决什么问题

无人机不是一块“飞控板”，而是机械、推进、电源、实时控制、状态估计、无线通信、机器人感知、安全工程和法规共同组成的空中机器人。入门者最常见的问题不是资料太少，而是资料彼此割裂：会调参数却不理解闭环，会写算法却不了解振动和时延，会画 PCB 却不清楚故障降级，会跑仿真却没有形成可安全上机的验证链。

本知识库把学习拆成四条相互依赖的主线：

1. **能飞起来**：结构、动力、电源、传感器、嵌入式和姿态控制。
2. **能稳定导航**：坐标系、状态估计、GNSS、视觉惯性、轨迹与任务。
3. **能形成产品**：通信、图传、地面站、安全状态机、测试、量产和合规。
4. **能持续研发**：仿真、日志、自动测试、开源代码阅读、硬件在环和数据闭环。

## 三、推荐使用方法

### 3.1 初学者

先读 01 和 02，不要立刻购买高功率整机。用 Python/Octave 完成一维滤波和简单闭环，再用 PX4 或 ArduPilot 的软件在环仿真完成起飞、悬停、航点和失效场景。只有在能解释日志、坐标系、解锁条件和失控保护之后，才进入无桨台架与低风险真机验证。

### 3.2 已有嵌入式经验者

重点补齐 03、06、07。无人机实时软件的难点不是“会不会写 SPI”，而是采样时间戳、传感器相位延迟、缓存一致性、调度抖动、振动混叠和错误数据如何穿透控制闭环。

### 3.3 已有算法经验者

重点补齐 04、05、11。仿真中正确的算法，上机后可能因外参、滚动快门、曝光、时间同步、温漂、算力抖动、链路丢包和安全状态机而失败。任何智能模块都不应绕过基础飞控的实时安全边界。

### 3.4 已有硬件经验者

重点补齐 06、07、10。飞控硬件不是“MCU + IMU”的器件拼装，必须从噪声、供电、布局、热漂、时钟、冗余、日志吞吐、升级恢复和软件生态共同评价。

## 四、学习成果判定

真正掌握不能只以“看完”或“能起飞”判定。建议使用以下证据：

|    层级 | 可验证成果                                 | 不足以证明掌握的现象 |
| ------: | :----------------------------------------- | :------------------- |
| L1 概念 | 能画出整机数据流、能解释坐标系与闭环       | 会背名词和型号       |
| L2 计算 | 能完成推重比、续航、带宽、采样率与链路预算 | 只会套在线计算器     |
| L3 仿真 | 能复现实验、注入故障、解释日志             | 只让仿真机起飞       |
| L4 台架 | 无桨验证方向、时序、保护和热状态           | 只看到电机转动       |
| L5 飞行 | 按门禁试飞，记录配置、环境、日志和复盘     | “飞了几次没出事”     |
| L6 研发 | 有版本、需求、测试矩阵、回归与发布证据     | 手工改参数且无法复现 |

## 五、必须始终遵守的安全底线

- 仿真优先、去桨调试、受控供电、限制电流、设置物理安全区。
- 电池、螺旋桨和高速电机都可造成火灾或严重人身伤害；充放电、运输和存储遵循厂家规范。
- 首飞前核对当地最新法规、空域、实名登记、运行识别、人员资质和保险要求。
- 不在人员、道路、机场、敏感设施或未经授权的私有区域上空测试。
- 不把 AI 输出直接当作无条件执行命令；必须有置信度、边界、超时、人工接管和安全降级。
- 本知识库不是适航批准、法律意见或具体机型飞行手册，法规与标准需在每次项目启动时重新核验。
