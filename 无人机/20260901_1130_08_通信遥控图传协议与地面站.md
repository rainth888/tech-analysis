# 通信、遥控、图传、协议与地面站

## 一、通信系统分层

无人机可能同时具有遥控、遥测、图传、GNSS 差分、Remote ID、机内总线、载荷链路和蜂窝/卫星链路。应按业务重要度分开设计，不让高清视频流量挤占控制命令。

| 业务          | 时延敏感 | 带宽 |  丢包容忍   |     安全优先级     |
| :------------ | :------: | ---: | :---------: | :----------------: |
| 控制/接管     |   极高   |   低 |     低      |        最高        |
| 状态遥测/告警 |    高    | 中低 |     中      |         高         |
| 任务/参数     |    中    |   低 | 需确认/重传 |         高         |
| 视频预览      |    高    |   高 | 可容忍部分  |         中         |
| 媒体下载      |    低    | 很高 |   可重传    |         低         |
| 日志/OTA      |   中低   | 中高 |  必须完整   | 高但不应飞行中抢占 |

## 二、射频和链路预算

### 2.1 基本预算

$$
P_r=P_t+G_t+G_r-L_{path}-L_{cable}-L_{misc}
$$

接收功率需高于接收灵敏度并保留衰落裕量。自由空间模型只是起点，低空多径、机体遮挡、姿态变化、天线极化、树木建筑、地面反射和同频干扰都会改变链路。

### 2.2 Fresnel 区与视距

“能看到无人机”不等于无线传播路径完全无遮挡。地形、树木和建筑侵入 Fresnel 区会增加损耗。天线安装需考虑机体碳纤维、电池、相机、云台和人体遮挡。

### 2.3 频段和法规

发射功率、占用带宽、频率和设备型号核准受国家/地区法规约束。不要用技术可实现性替代合规性。跨地区产品需要区域配置、防篡改和硬件能力边界。

## 三、遥控链路

### 3.1 RC 数据

通道不仅有摇杆，还包括模式、解锁和紧急动作。校准要处理中心、端点、死区、反向、丢帧和 failsafe 值。接收机输出协议可能包括 SBUS、CRSF、DSM 等，电气电平和反相要求不同。

### 3.2 链路质量

RSSI、LQ、SNR、丢帧和延迟反映不同维度。仅以百分比图标设阈值不可靠，应结合协议定义、更新率和实测退化曲线。

### 3.3 失联

区分短时丢帧、持续失联、遥控器关机、接收机重启和链路恢复。恢复后是否自动接管要防止摇杆位置突变，通常需要明确接管条件。

## 四、MAVLink

### 4.1 定位

MAVLink 是轻量无人机消息协议，承载遥测、命令、参数、任务、相机、云台、文件和 Open Drone ID 等微服务。它不是无线物理层，可运行在串口、UDP、TCP 等传输上。

### 4.2 系统与组件

每架载具是 system，飞控、相机、云台等可作为 component。路由器需要正确处理广播、定向消息和多个链路，避免 system ID 冲突。

### 4.3 常用微服务

| 微服务        | 功能                 | 实现要点                           |
| :------------ | :------------------- | :--------------------------------- |
| Heartbeat     | 存活、类型、模式摘要 | 超时不等于立即坠机动作，需分层处理 |
| Command       | 执行动作并 ACK       | 重复、超时、进行中、拒绝原因       |
| Mission       | 上传/下载任务        | 序号、重传、完整性和坐标类型       |
| Parameter     | 读写参数             | 类型、版本、持久化和权限           |
| TIMESYNC      | 时钟估计             | 往返时延、异常值和漂移             |
| FTP           | 文件传输             | 路径权限、断点、带宽和完整性       |
| Camera/Gimbal | 载荷控制             | 能力发现、状态和多组件路由         |

### 4.4 安全

MAVLink 2 支持消息签名以验证来源和完整性，但不等于加密所有内容。密钥管理、防重放、链路加密、网络隔离和命令授权仍需系统设计。

## 五、地面站

### 5.1 功能

设备发现、固件升级、传感器校准、参数配置、地图/任务、遥测、告警、日志和载荷控制。QGroundControl 与 PX4/MAVLink 生态紧密；Mission Planner 常用于 ArduPilot。选择要看目标飞控和工作流。

### 5.2 人机工程

- 高优先级告警可见、可听且给出动作。
- 单位、坐标和高度基准明确。
- 危险操作二次确认但不阻塞紧急操作。
- 飞行模式名称与实际控制权一致。
- 断链/重连后不默默执行陈旧命令。
- 参数批量修改有差异、备份、验证和回滚。

## 六、SDK 与 Offboard 控制

MAVSDK、ROS 2、pymavlink 等可实现任务或伴随计算。Offboard 需要持续 setpoint、健康心跳和超时策略。程序崩溃、进程暂停、网络阻塞或时间戳错误时，飞控必须退出到预定义安全模式。

建议命令路径：

```text
任务意图
 -> 合法性/权限
 -> 坐标与时间校验
 -> 速度/加速度/地理边界
 -> 连续 setpoint
 -> 飞控模式与 ACK
 -> 实际状态确认
```

## 七、数字图传

### 7.1 视频流水线

```text
CMOS曝光 -> ISP -> 缩放/降噪 -> H.264/H.265编码
 -> 分包/FEC/重传策略 -> 无线链路
 -> 缓冲/解码 -> 显示
```

端到端时延包含曝光等待、ISP、编码帧结构、网络排队、抖动缓冲、解码和显示。只报告空口延迟没有意义。

### 7.2 码率、质量与时延

更长 GOP 和更大缓冲可能提高压缩效率/抗抖动，但增加恢复和时延。低延迟链路常使用更短队列、灵活码率、优先帧和丢包隐藏。飞行控制视频与高质量录像通常是两条不同目标的流水线。

### 7.3 自适应

根据 SNR、丢包、队列和运动内容调整调制编码、分辨率、帧率和码率。自适应要避免频繁震荡，并保证控制/遥测保底带宽。

## 八、蜂窝和云连接

4G/5G 可扩展覆盖和机队管理，但运营商网络时延、切换、NAT、断网、资费和覆盖不可控。远程命令需要设备身份、双向认证、最小权限、审计、重放保护和明确的本地自治边界。

云断开时飞行安全不能依赖远端服务；远端恢复后也不能自动补发过期命令。

## 九、机内网络与时间

伴随计算、相机和飞控可用 UART、CAN 或 Ethernet。网络化架构需处理 QoS、拥塞、服务发现、版本和时间同步。ROS 2 DDS 的可靠性设置不是越可靠越好：高频传感器允许丢旧包而不应堆积，命令/配置则需要确认。

## 十、通信测试

### 10.1 实验维度

- 距离、方向、姿态、天线遮挡和高度。
- 同频/邻频干扰、多人热点和机载电子噪声。
- 带宽、丢包、突发丢包、时延、抖动、乱序和重复。
- 控制/视频/日志并发，CPU/内存/热满载。
- 断开、重连、链路切换和地面站重启。

### 10.2 指标

报告分位数而非只给平均值：P50/P95/P99 时延、最长连续丢包、恢复时间、有效吞吐、控制截止期违例和错误动作次数。

## 十一、本章实践与验收

1. 计算一个 2.4 GHz/5.8 GHz 假设链路预算，并列出模型未覆盖因素。
2. 用 MAVSDK 连接 SITL，完成命令 ACK、超时和重复命令处理。
3. 限制网络带宽并叠加视频流，证明控制链路仍有保底。
4. 让 Offboard 程序暂停 2 秒，验证飞控按预定策略退出。
5. 测量相机曝光到屏幕显示的端到端时延分布。
