# 开源飞控与机器人生态源码导读

## 一、先按目标选择生态

| 项目           | 主要定位                       | 适合学习                                    | 不应误解为                 |
| :------------- | :----------------------------- | :------------------------------------------ | :------------------------- |
| PX4            | 模块化通用自动驾驶仪           | 架构、NuttX、uORB、控制、估计、ROS 2/MAVSDK | 开箱即适合所有定制硬件     |
| ArduPilot      | 多车型、功能丰富的自动驾驶系统 | 车辆功能、任务、导航、日志、广泛硬件        | 只用于航模配置             |
| Betaflight     | FPV/竞速高性能飞控             | 高频控制、滤波、Blackbox、资源受限 MCU      | 通用自主导航平台           |
| INAV           | 导航型航模/多机型              | GPS 导航、航模与易用配置                    | PX4/ArduPilot 的完全替代品 |
| Paparazzi UAV  | 学术和自主飞行生态             | 模块化、地面站、研究平台                    | 主流消费级产品固件模板     |
| QGroundControl | MAVLink 地面站                 | 参数、任务、遥测、跨平台 UI                 | 飞控实时安全核心           |
| MAVLink        | 消息与微服务协议               | 机载组件/地面站互操作                       | 无线电或加密隧道本身       |
| MAVSDK         | MAVLink 高层 SDK               | 任务、遥测、伴随计算                        | 绕过飞控安全检查的接口     |
| ROS 2          | 机器人中间件                   | 感知、规划、伴随计算                        | 默认硬实时飞控             |
| Gazebo         | 物理/传感器仿真                | SITL、环境、视觉和回归                      | 真实世界的完整替代         |

## 二、许可证必须在选型时理解

常见情况：PX4 核心代码采用宽松 BSD 3-Clause；ArduPilot、Betaflight、INAV 等使用 GPL 系列；MAVLink 消息定义/生成 C 库与生成器、文档存在不同许可；QGroundControl、MAVSDK、ROS 2 各仓库/组件也需查看实际 LICENSE。

工程上要区分：

- 使用已编译软件、修改并分发、链接库、网络服务和硬件产品的义务不同。
- 仓库可能包含不同许可证的子模块、模型、字体、地图或媒体资源。
- “开源”不等于无商标、无专利、无出口或无线电合规问题。
- 每次冻结版本时生成软件物料清单（SBOM）和第三方许可清单。

本文只给学习方向，不构成法律意见；产品发布前由合格人员复核具体版本许可。

## 三、PX4 学习路径

### 3.1 先做什么

1. 使用官方稳定版本文档搭建环境。
2. 运行 `make px4_sitl gz_x500` 一类官方示例（具体命令以所选版本文档为准）。
3. 连接 QGroundControl，完成解锁、起飞、模式、任务和日志。
4. 再阅读开发版 `main` 文档了解新架构，避免把开发分支直接用于真机。

### 3.2 核心概念

- NuttX/POSIX 环境、模块和 work queue。
- uORB 发布订阅消息。
- 参数、事件、日志和启动脚本。
- EKF2 等估计模块。
- multicopter attitude/rate/position control。
- control allocation 与 actuator output。
- commander、navigator、failsafe 和 flight mode。

### 3.3 源码追踪任务

以陀螺为例，追踪：驱动发布→sensor selection/correction→vehicle angular velocity→rate controller→vehicle torque setpoint→control allocator→actuator motors→输出驱动。记录每条 topic 的单位、坐标、发布率和时间戳。

### 3.4 第一个扩展

先写一个只订阅并发布诊断数据的小模块，随后加入参数和单元测试。不要把第一个改动放到执行器或解锁安全路径。

## 四、ArduPilot 学习路径

### 4.1 SITL 与工具

从官方开发文档运行 Copter SITL，使用 Mission Planner/MAVProxy 等连接。理解 vehicle code、AP_HAL、scheduler、libraries、parameter、mode 和 logging。

### 4.2 源码追踪

选择一个模式，从 mode update 到位置/姿态控制库，再到 motor output；追踪 EKF 状态和 failsafe 如何影响模式。ArduPilot 功能广，适合“纵向切一条链”，不要从目录逐文件阅读。

### 4.3 Lua 与扩展

脚本适合受限任务逻辑和原型，但要理解脚本调度、权限、资源和失败行为。飞行安全底线不应依赖可能停止的高层脚本。

## 五、Betaflight 与 INAV

### 5.1 Betaflight

重点学习 gyro sampling、滤波、PID loop、mixer、DShot、Blackbox、目标板和资源映射。适合研究低延迟和振动，但其目标更偏手动/FPV 飞行。

### 5.2 INAV

在航模与 GPS 辅助导航之间提供较低门槛，可学习传感器、模式和导航配置。若目标是复杂自主、伴随计算和研究型 VIO，应评估 PX4/ArduPilot 生态。

## 六、Paparazzi、Crazyflie 与教学平台

Paparazzi 适合学术研究和多种飞行器；Crazyflie 软硬件资料开放、机体小、实验能量低，适合室内定位、控制和多机研究入门。低能量不等于无风险，仍需桨保护、场地和电池规范。

## 七、QGroundControl、MAVLink 与 MAVSDK

### 7.1 QGroundControl

源码可用于学习 Qt/QML 地面站、Vehicle 抽象、MAVLink 接入、参数元数据、任务规划和固件升级。定制时要保留协议兼容、告警、升级校验和危险操作保护。

### 7.2 MAVLink

先读消息结构和 routing，再读 Heartbeat、Command、Mission、Parameter、Camera/Gimbal、FTP、TimeSync。只有确认现有 common dialect 无法表达需求时才新增消息，避免私有协议碎片化。

### 7.3 MAVSDK

从 telemetry/action/mission 开始，处理异步结果、超时和状态确认。Offboard 示例必须加入连接丢失、setpoint 停止和进程退出测试。

## 八、ROS 2、Gazebo 与 OpenCV

### 8.1 ROS 2

学习 package、node、topic、service、action、parameter、launch、TF2、rosbag2 和 QoS。连接飞控时使用官方桥接/接口文档，核对坐标转换和消息版本。

### 8.2 Gazebo

学习 world、model、SDF、physics、sensor、plugin 和 transport。逐步加入风、传感器噪声、延迟和故障。仿真模型参数必须有来源并与实测校准。

### 8.3 OpenCV

从图像读写、颜色/滤波、特征、光流、相机标定、PnP 和双目开始。OpenCV API 会随版本变化，应固定 4.x 的具体版本并链接相应文档。

## 九、飞控操作系统

- NuttX：PX4 等飞控使用的 POSIX 风格 RTOS，适合学习板级移植、驱动和文件系统。
- FreeRTOS：适合独立节点、ESC/载荷/安全 MCU 和自研实验。
- Zephyr：适合网络化传感器、CAN/蓝牙节点和现代嵌入式生态探索。

选择 RTOS 前定义任务、截止期、内存、协议、认证/安全需求和维护能力。

## 十、正确读大型开源代码的方法

### 10.1 五遍法

1. 运行：先让官方示例可重复。
2. 架构：画进程/模块、消息和启动顺序。
3. 数据链：追踪一个物理量从驱动到执行器。
4. 异常链：追踪超时、无效和故障模式。
5. 变更：做一个小改动，写测试并比较日志。

### 10.2 不要做

- 在没固定版本和参数时比较结果。
- 同时修改估计、控制和结构参数。
- 只看 happy path，不读 timeout/failsafe。
- 从博客复制旧命令而不看当前官方版本。
- 把上游开发分支或第三方 fork 直接刷到真机。

## 十一、开源选型决策表

| 问题                                | 选择倾向                     |
| :---------------------------------- | :--------------------------- |
| 通用自主、多旋翼/固定翼/VTOL、ROS 2 | 优先评估 PX4                 |
| 车型广、任务功能成熟、实用生态      | 优先评估 ArduPilot           |
| FPV/竞速、低延迟手动操控            | 评估 Betaflight              |
| 航模导航、相对易配置                | 评估 INAV                    |
| 学术平台和定制研究                  | 评估 Paparazzi/Crazyflie/PX4 |
| 跨飞控地面站                        | QGroundControl/MAVLink 生态  |
| 应用/伴随计算 SDK                   | MAVSDK 或飞控官方 ROS 2 接口 |

## 十二、本章验收

1. 至少跑通一个 PX4 或 ArduPilot 稳定版 SITL。
2. 画出从 IMU 到电机输出的数据链及频率。
3. 注入一个传感器或链路故障，定位源码中的检测与动作路径。
4. 做一个非安全关键模块改动，配套单元/SITL 测试。
5. 为所用仓库和依赖生成版本与许可证清单。
