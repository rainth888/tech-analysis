# ToF 摄像头原理、参数解释与 C005 驱动调制方案

本文以 RK3576 平台上的 C005 iToF 摄像头为例，说明 ToF 摄像头的成像原理、Web 页面中各参数的含义、点云/深度/幅度图如何理解，以及从硬件到驱动再到 Web 展示的完整调试方案。

本文用于技术分析，不记录板端私有 IP、账号、密钥等敏感信息。

---

## 1. ToF 摄像头是什么

ToF 是 Time of Flight，即“飞行时间”。摄像头主动发出不可见红外光，红外光打到物体后反射回来，传感器根据光的往返时间或相位差计算距离。

常见 ToF 分两类：

| 类型        | 英文              | 测距方式                         | 特点                             |
|-------------|-------------------|----------------------------------|----------------------------------|
| dToF        | Direct ToF        | 直接测量光脉冲往返时间           | 精度高，常用于 LiDAR             |
| iToF        | Indirect ToF      | 测量调制光的相位差               | 更适合摄像头模组，输出深度图     |

C005 属于 iToF 模组。它不是普通 RGB 摄像头，而是主动红外深度摄像头。它输出的核心不是彩色图，而是：

| 输出             | 含义                                             |
|------------------|--------------------------------------------------|
| Distance / Depth | 每个像素对应的距离，通常单位是 mm                |
| Amplitude        | 每个像素收到的红外反射强度                       |
| Point Cloud      | 把二维深度像素转换到三维空间后的点集合           |

---

## 2. iToF 的测距原理

iToF 的基本流程如下：

```text
红外发射器发出调制光
        ↓
光照到目标表面
        ↓
目标反射红外光
        ↓
传感器接收反射光
        ↓
比较发射信号与接收信号的相位差
        ↓
计算距离
```

如果调制光频率为 `f`，相位差为 `phase`，则距离和相位差近似满足：

```text
distance ∝ phase / modulation_frequency
```

更直观地说：

- 近处物体反射光回来得早，相位差小。
- 远处物体反射光回来得晚，相位差大。
- 相位差经过标定、温度补偿、滤波后变成距离值。

iToF 通常会采集多个相位帧，例如 0°、90°、180°、270°，再通过算法计算：

```text
相位 phase
幅度 amplitude
置信度 confidence
距离 distance
```

## 3. 为什么需要调制光

ToF 摄像头不是单纯“照亮再拍照”，而是“用特定频率调制红外光，再解调回波”。

调制的作用：

| 作用             | 说明                                                           |
|------------------|----------------------------------------------------------------|
| 区分主动光       | 从环境红外光中分离摄像头自己发出的红外光                       |
| 计算相位差       | 根据调制信号发射和接收之间的相位偏移计算距离                   |
| 支持多频解算     | 用不同频率降低距离歧义，提高有效测距范围                       |
| 提供幅度信息     | 回波强弱可以反映目标反射能力和测距可信度                       |

C005 SDK 中可以看到类似参数：

| 参数                     | 含义                                       |
|--------------------------|--------------------------------------------|
| `C005_ILLU_FREQ1`        | 第一组照明调制频率                         |
| `C005_ILLU_FREQ2`        | 第二组照明调制频率                         |
| `C005_CID_FREQ1_EXP_TIME`| 第一组频率对应的积分/曝光时间              |
| `C005_CID_FREQ2_EXP_TIME`| 第二组频率对应的积分/曝光时间              |

驱动和 SDK 的任务之一，就是保证：

```text
传感器相位采集时序
照明驱动调制频率
曝光/积分时间
ISP 解算参数
EEPROM 标定参数
```

这些内容彼此匹配。任意一环不匹配，都可能出现有 MIPI 帧但无有效距离，或者幅度很低、距离全是无效值。

## 4. ToF 一帧数据里通常有什么

C005 用户态 SDK 当前取到的是一组复合数据。Web 页面上主要展示如下内容：

| Web 显示项                 | 数据来源                       | 技术含义                                     |
|----------------------------|--------------------------------|----------------------------------------------|
| Distance                   | `c005_get_dist_and_amp()`       | 深度图，显示每个像素的距离                   |
| Amplitude                  | `c005_get_dist_and_amp()`       | 幅度图，显示红外反射强度                     |
| Point Cloud                | 深度图 + 相机内参              | 将深度像素投影成三维点                       |
| 3D Model                   | 点云固定视角投影               | 用三维方式预览物体空间形态                   |
| center distance            | 深度图中心像素                 | 画面中心点的距离                             |
| ROI distance mean          | 中心区域有效点均值             | 比中心单点更稳定的距离估计                   |
| ROI valid count            | 中心区域有效深度点数量         | 判断测距结果是否可靠                         |
| amplitude max              | ROI 或全局幅度最大值           | 判断主动红外回波是否足够强                   |
| exposure                   | SDK/驱动曝光或积分时间         | 影响相位帧采集和回波强度                     |
| temperature                | sensor / illumination / NTC     | 判断模组和照明是否过热                       |

## 5. 当前 Web 参数逐项解释

示例状态：

```text
中心无有效距离，ROI均值606mm/有效点2，amp=6/max=210，
fps=0，exp=2700us，temp=65.2C。
前后移动目标时距离和亮度图应同步变化。

frame=0 dist=65300 amp=4 fps=0 exp=100us temp=33.3
Distance
Amplitude
Point Cloud（采样）
```

### 5.1 中心无有效距离

`中心无有效距离` 表示画面中心像素的距离值当前不可用。

常见原因：

| 原因             | 说明                                                       |
|------------------|------------------------------------------------------------|
| 中心点无物体     | 人或纸板没有正好落在中心像素                               |
| 中心点幅度低     | 中心像素收到的红外回波太弱                                 |
| 中心点过曝       | 反射太强导致该点无效                                       |
| 中心点被过滤     | ISP 判断该点置信度不足                                     |
| 距离哨兵值       | 输出 `65300`、`65500` 等无效值                              |

因此，`中心无有效距离` 不等于整幅图无效。应该结合 ROI 均值和有效点数量看。

### 5.2 ROI均值606mm/有效点2

ROI 是 Region of Interest，即关注区域。当前 Web 使用画面中心附近的一个小区域统计有效距离。

```text
ROI均值606mm
```

表示中心区域里有效点的平均距离约为 606 mm。

```text
有效点2
```

表示 ROI 区域里只有 2 个像素被判为有效。

这个结果的判断：

| 现象             | 判断                                                       |
|------------------|------------------------------------------------------------|
| ROI 均值有数值   | 局部已经有有效测距点                                       |
| 有效点只有 2     | 结果还很稀疏，不适合作为稳定距离输出                       |
| 有效点几十个     | 可以初步观察距离趋势                                       |
| 有效点几百个以上 | 更适合做稳定性和误差评估                                   |

所以 `ROI均值606mm/有效点2` 的含义是：

```text
局部已经测到约 606mm 的距离，但有效点太少，可信度还不高。
```

### 5.3 amp=6/max=210

`amp` 是 amplitude，即幅度/回波强度。

| 字段      | 含义                                       |
|-----------|--------------------------------------------|
| `amp=6`   | 中心像素的幅度值                           |
| `max=210` | 当前统计范围内幅度最大值                   |

幅度越高，说明收到的主动红外回波越强。幅度太低时，深度容易无效或跳动。

经验判断：

| 幅度表现             | 判断                                                       |
|----------------------|------------------------------------------------------------|
| `max < 20`           | 极弱，通常没有有效主动回波                                 |
| `max` 几十到几百     | 有回波，但深度可能稀疏                                     |
| `max` 上千           | 主动回波明显，通常能看到人影或平面                         |
| 中心 amp 很低        | 中心点可能无效，但其他区域仍可能有效                       |

因此 `amp=6/max=210` 表示：

```text
中心点回波很弱，但画面中某些位置已经有较明显回波。
```

### 5.4 fps=0

这里的 `fps=0` 不是 Web 页面完全不刷新。它通常表示 SDK 的 `c005_get_fps()` 没有给出有效帧率，或驱动/SDK 中记录帧率的字段没有正确更新。

实际刷新应看：

| 判断方式        | 说明                                     |
|-----------------|------------------------------------------|
| `frame` 是否递增 | 最直接，递增说明采集循环正在跑           |
| Distance 是否变化 | 目标移动时深度图变化说明取帧正常        |
| Amplitude 是否变化 | 目标移动时幅度图变化说明回波在变化      |

后续驱动可完善 `fps` 统计，让 Web 显示真实采集帧率。

### 5.5 exp=2700us / exp=100us

`exp` 是 exposure 或 integration time，即曝光/积分时间。

ToF 中曝光不是普通 RGB 相机意义上的“亮一点/暗一点”那么简单，它影响相位采集时长和回波强度。

| 曝光时间       | 影响                                           |
|----------------|------------------------------------------------|
| 太短           | 回波弱，Amplitude 低，深度无效点多             |
| 适中           | 回波稳定，深度点更多                           |
| 太长           | 近距离或高反射目标可能过曝                     |

当前曾做过曝光扫描：

```text
100us → 6000us
```

如果曝光增加后幅度仍不变，说明问题不只是曝光短，可能是照明、光路、反射目标、调制参数或标定参数问题。

### 5.6 temp=65.2C

`temp` 是温度，通常来自传感器、照明驱动或 NTC。

当前 Web 后续已改为显示三个温度：

```text
temp=sensor/illu/ntc C
```

含义：

| 温度项        | 说明                                             |
|---------------|--------------------------------------------------|
| sensor        | ToF sensor 内部或附近温度                         |
| illu          | illumination driver / VCSEL 照明相关温度          |
| ntc           | 板上热敏电阻测得的模组温度                        |

温度过高会影响：

| 影响             | 说明                                           |
|------------------|------------------------------------------------|
| 距离漂移         | 相位和标定参数受温度影响                       |
| 噪声增加         | 深度点变少或跳动                               |
| 保护风险         | VCSEL/照明驱动可能需要降功率或暂停              |

建议：

| 条件                 | 操作                                           |
|----------------------|------------------------------------------------|
| `illu >= 85C`        | 暂停长时间测试，先散热                         |
| `ntc >= 75C`         | 暂停长时间测试，检查散热和 3.6V 供电            |
| 温度持续上升         | 降低曝光、降低帧率或加入温度保护策略            |

### 5.7 frame=0

`frame` 是 Web viewer 内部帧计数。

| 表现         | 判断                                               |
|--------------|----------------------------------------------------|
| frame 递增   | Web 采集线程持续取帧                               |
| frame 不变   | 采集线程可能卡住，或某个 SDK 调用阻塞              |

当前曾发现原厂点云接口可能拖慢或卡住刷新，因此 Web viewer 采用轻量点云预览。

### 5.8 dist=65300

`65300` 当前按无效距离或超量程哨兵值处理。

不要把它当成 65.3 米。

判断逻辑：

```text
dist == 0       → 无效
dist >= 65000   → 无效/超量程
0 < dist < 65000 → 可能有效，仍需结合 amp 和 ROI 判断
```

### 5.9 Distance

Distance 是深度图。

看法：

| 现象               | 判断                                           |
|--------------------|------------------------------------------------|
| 全黑               | 没有有效深度点，或有效点太少                   |
| 人影轮廓可见       | 深度解算已经有结果                             |
| 平面区域连续       | 距离稳定性较好                                 |
| 大量白点/黑洞      | 无效点、边缘噪声、反光、过曝或过滤不足          |

### 5.10 Amplitude

Amplitude 是红外回波强度图，不是普通灰度图。

看法：

| 现象               | 判断                                           |
|--------------------|------------------------------------------------|
| 全黑               | 回波极弱或照明未生效                           |
| 人/纸板变亮        | 主动红外回波存在                               |
| 桌面特别亮         | 桌面对红外反射更强，或距离更近                 |
| 局部过亮           | 可能造成深度无效或孔洞                         |

### 5.11 Point Cloud（采样）

Point Cloud 是点云。它把深度图里的有效像素转换成三维点。

基本公式：

```text
Z = depth_mm
X = (u - cx) * Z / fx
Y = (v - cy) * Z / fy
```

其中：

| 参数 | 含义                           |
|------|--------------------------------|
| `u`  | 像素横坐标                     |
| `v`  | 像素纵坐标                     |
| `Z`  | 深度值                         |
| `fx` | 水平方向焦距，单位为像素       |
| `fy` | 垂直方向焦距，单位为像素       |
| `cx` | 光心横坐标                     |
| `cy` | 光心纵坐标                     |

当前 Web 中的点云是预览用途：

| 点云面板                  | 用途                                               |
|---------------------------|----------------------------------------------------|
| Point Cloud（俯视）       | 看左右位置和远近趋势                               |
| 3D Model（相机坐标）      | 用固定视角看物体的三维形态                         |

## 6. 如何看点云是否正确

点云正确性不是看“像不像照片”，而是看空间趋势是否符合物理事实。

### 6.1 平面测试

用白纸板或墙面做测试。

| 操作                      | 正确表现                                           |
|---------------------------|----------------------------------------------------|
| 纸板放在正前方 50cm       | 点云形成一团或一片比较集中的点                     |
| 纸板固定不动              | 点云位置基本稳定，不应大幅跳动                     |
| 纸板前后移动              | 点云整体远近方向同步移动                           |
| 纸板左右移动              | 点云整体左右方向同步移动                           |

### 6.2 距离测试

让纸板分别位于 40cm、80cm、120cm。

| 距离           | 期望结果                                           |
|----------------|----------------------------------------------------|
| 40cm           | ROI 均值接近 400mm，点云更靠近                     |
| 80cm           | ROI 均值接近 800mm，点云居中                       |
| 120cm          | ROI 均值接近 1200mm，点云更远                      |

允许先有误差，第一阶段重点看趋势是否正确。

### 6.3 左右方向测试

| 操作             | 正确表现                                         |
|------------------|--------------------------------------------------|
| 纸板在画面左侧   | 点云偏左                                         |
| 纸板在画面中央   | 点云靠近中心参考线                               |
| 纸板在画面右侧   | 点云偏右                                         |

如果方向相反，通常是显示坐标需要翻转，不一定是传感器或驱动错误。

### 6.4 前景/背景测试

人坐在 80cm，手伸到 40cm。

| 区域     | 正确表现                                           |
|----------|----------------------------------------------------|
| 手       | 深度更近，点云中出现更近的一簇点                   |
| 身体     | 深度更远，点云在后面                               |
| 背景     | 更远或无效                                         |

## 7. 当前 C005 驱动链路

当前链路可以抽象为：

```text
C005 模组
  ├─ I2C4: 寄存器、固件、照明驱动配置
  ├─ MCLK: 24MHz 输入时钟
  ├─ RESET: 复位控制
  ├─ 3.3V / 1.8V / 3.6V: 供电
  └─ MIPI CSI-2: 相位帧数据输出

RK3576
  ├─ c005 kernel driver
  ├─ csi2_dphy2
  ├─ mipi2_csi2
  ├─ rkcif_mipi_lvds2
  ├─ V4L2 video device
  └─ user-space C005 SDK

Web viewer
  ├─ c005_get_dist_and_amp()
  ├─ Distance / Amplitude preview
  ├─ lightweight point cloud
  └─ 3D model preview
```

关键点：

| 模块             | 责任                                               |
|------------------|----------------------------------------------------|
| 设备树           | 描述 I2C、MIPI、时钟、reset、media graph            |
| 内核驱动         | 实现 subdev、I2C 寄存器读写、stream on/off、V4L2 控制 |
| SDK              | 写入 firmware/ISM/illumination/sensor 参数，执行 ISP 解算 |
| Web viewer       | 展示深度、幅度、点云和诊断状态                     |

## 8. 编写和调制 ToF 驱动的方案

### 8.1 第一阶段：硬件通路确认

目标是让芯片能被识别。

| 检查项          | 目标                                               |
|-----------------|----------------------------------------------------|
| 1.8V            | I2C、MCLK、RESET 电平域正确                         |
| 3.3V            | 模组主供电正常                                     |
| 3.6V            | VCSEL/照明供电正常                                 |
| RESET           | 上电后能从低变高                                   |
| MCLK            | 24MHz 输出稳定                                     |
| I2C             | 地址 `0x3d` 可 ACK，chip id 可读                    |
| FPC             | 方向、压紧、引脚映射正确                           |

验收点：

```text
chip id = 0x2468
```

### 8.2 第二阶段：设备树和 media graph

目标是让 RK3576 正确建立摄像头链路。

| 内容              | 说明                                               |
|-------------------|----------------------------------------------------|
| I2C 节点          | `c005@3d`                                          |
| clock             | 24MHz MCLK                                         |
| reset-gpios       | 复位 GPIO                                          |
| data-lanes        | 2-lane MIPI                                        |
| link-frequencies  | MIPI 速率                                          |
| remote-endpoint   | sensor → DPHY → CSI2 → RKCIF                       |

当前 C005 实际使用 split CSI2 路径：

```text
csi2_dphy2 -> mipi2_csi2 -> rkcif_mipi_lvds2
```

### 8.3 第三阶段：内核驱动

内核驱动至少要实现：

| 功能               | 说明                                               |
|--------------------|----------------------------------------------------|
| probe              | 获取 clock/GPIO，读 chip id                         |
| s_power            | 上下电/复位控制                                     |
| s_stream           | 写 stream on/off 寄存器                              |
| pad ops            | 设置 mbus code、分辨率、帧格式                       |
| custom controls    | fps、曝光、sensor power 等 V4L2 控制                 |
| debug register     | 支持 SDK 通过 `VIDIOC_DBG_*` 写厂商寄存器             |

ToF 驱动和普通 RGB sensor 驱动不同：

| 普通 RGB 驱动           | ToF 驱动                                                   |
|-------------------------|------------------------------------------------------------|
| 输出 RAW/YUV 图像       | 输出相位帧或复合帧                                         |
| ISP 负责颜色处理        | SDK/ISP 负责相位解算、深度计算、标定补偿                   |
| 主要调曝光/增益         | 还要调调制频率、照明驱动、积分时间、温度补偿、无效点过滤   |

### 8.4 第四阶段：用户态 SDK 初始化

SDK 通常执行：

```text
读取 EEPROM 标定
写 firmware registers
写 ISM settings
写 illumination driver settings
写 sensor init registers
启动 V4L2 stream
取 raw phase frame
调用 ISP library 解算 depth/amp
```

如果任一步失败，可能表现为：

| 表现                 | 可能原因                                           |
|----------------------|----------------------------------------------------|
| I2C 无 ACK           | FPC、供电、reset、I2C 线序问题                      |
| stream on 无帧       | MIPI lane、DPHY 路径、时钟、frame format 问题        |
| 有帧但 Distance 全无效 | 照明、调制、曝光、EEPROM 标定或 ISP 参数问题          |
| Amplitude 很低       | VCSEL 未亮、目标太远/太黑、光路遮挡、曝光太短        |
| 温度过高             | VCSEL/照明功耗高，散热不足                          |

### 8.5 第五阶段：Web 可视化和验收

Web 不只是展示画面，还要帮助判断驱动状态。

建议 Web 展示：

## 10. ToF 摄像头常见参数体系

ToF 摄像头的参数不能只看分辨率。它同时涉及光学、照明、调制、传感器、深度算法、标定、温度和接口链路。

### 10.1 成像与深度参数

| 参数                 | 含义                                               | 对效果的影响                                     |
|----------------------|----------------------------------------------------|--------------------------------------------------|
| Depth Resolution     | 深度图分辨率，例如 640x480                         | 决定深度点数量和点云密度                         |
| Raw Phase Resolution | 原始相位帧分辨率                                   | 决定 ISP 解算输入质量                            |
| Depth Range          | 有效测距范围，例如 0.2m~5m                         | 决定适用场景                                     |
| Minimum Range        | 最近可测距离                                       | 太近可能过曝或相位解算失败                       |
| Maximum Range        | 最远可测距离                                       | 受照明功率、目标反射率、环境光影响               |
| Depth Accuracy       | 距离准确度，例如 ±1cm 或 ±1%                       | 决定能否做测量级应用                             |
| Depth Precision      | 重复测量稳定性                                     | 固定目标时深度抖动大小                           |
| Depth Noise          | 深度噪声                                           | 噪声大时点云散、边缘毛刺多                       |
| Fill Rate            | 有效深度点比例                                     | 有效点越多，点云越完整                           |
| Invalid Value        | 无效距离哨兵值，例如 0、65300、65500               | 软件必须过滤，否则会误判为远距离                 |

### 10.2 幅度与置信度参数

| 参数                 | 含义                                               | 对效果的影响                                     |
|----------------------|----------------------------------------------------|--------------------------------------------------|
| Amplitude            | 红外回波强度                                       | 回波越强，深度通常越可靠                         |
| Confidence           | 深度可信度                                         | 可用于过滤无效点                                 |
| Min Amplitude        | 最小幅度阈值                                       | 阈值太低噪声多，阈值太高有效点少                 |
| Saturation           | 饱和标志                                           | 过曝区域深度可能无效                             |
| Ambient Light        | 环境光强度                                         | 强阳光会降低 ToF 信噪比                           |
| Reflectivity         | 目标反射率                                         | 黑色、透明、镜面材质通常难测                     |

当前 C005 Web 里看到的 `amp=6/max=210` 或 `amp max=2100`，就是幅度相关信息。`max` 从个位数提升到上千，通常说明主动红外回波已经明显存在。

### 10.3 光学参数

| 参数                 | 含义                                               | 对效果的影响                                     |
|----------------------|----------------------------------------------------|--------------------------------------------------|
| FOV                  | 视场角                                             | 决定能看到多宽、多高                             |
| Focal Length         | 焦距                                               | 影响视场角和点云投影                             |
| Lens Distortion      | 镜头畸变                                           | 会影响点云几何形状                               |
| Aperture             | 光圈                                               | 影响进光量和景深                                 |
| IR Bandpass Filter   | 红外窄带滤光片                                     | 抑制环境光，提高主动红外信噪比                   |
| Baseline             | ToF 模组中发射器与接收器相对位置                   | 影响遮挡、近距离阴影和多路径反射                 |
| Optical Center       | 光心 `cx/cy`                                       | 点云坐标转换必须使用                             |
| Focal Pixels         | 像素焦距 `fx/fy`                                   | 点云坐标转换必须使用                             |

点云从深度图变为三维点时，核心使用：

```text
X = (u - cx) * Z / fx
Y = (v - cy) * Z / fy
Z = depth
```

因此，`fx/fy/cx/cy` 不准确时，点云会出现比例不对、左右偏移、平面弯曲等问题。

### 10.4 照明与调制参数

| 参数                 | 含义                                               | 对效果的影响                                     |
|----------------------|----------------------------------------------------|--------------------------------------------------|
| VCSEL / LED Power    | 红外发射功率                                       | 功率不足则幅度低，功率过高则发热或近距过曝       |
| Illumination Voltage | 照明供电，例如 3.6V                                | 供电不足会导致回波弱                             |
| Modulation Frequency | 调制频率                                           | 影响距离范围和相位解算                           |
| Multi Frequency      | 多频调制                                           | 用于减少距离歧义                                 |
| Duty Cycle           | 调制占空比                                         | 影响平均光功率和温升                             |
| Phase Step           | 相位采样步进                                       | 影响相位计算精度                                 |
| Integration Time     | 积分时间                                           | 类似曝光，影响回波强度                           |

iToF 的调制频率越高，理论距离分辨率越好，但无歧义距离范围会变小。多频 iToF 通常通过不同频率组合解决范围和精度之间的矛盾。

### 10.5 曝光、帧率与动态范围参数

| 参数                 | 含义                                               | 对效果的影响                                     |
|----------------------|----------------------------------------------------|--------------------------------------------------|
| Exposure / Integration | 积分时间                                         | 太短回波弱，太长可能过曝                         |
| Auto Exposure        | 自动曝光                                           | 可提高不同距离/反射率下的可用性                  |
| Max Exposure         | 最大曝光限制                                       | 限制温度和帧率                                   |
| FPS                  | 帧率                                               | 影响实时性、运动模糊和发热                       |
| Frame Time           | 单帧时间                                           | 与 FPS 和曝光相关                                |
| HDR                  | 高动态范围                                         | 同时兼顾近处强反射和远处弱反射                   |

ToF 中的曝光更像“积分时间”。它不仅影响图像亮度，也影响相位测量质量。当前 C005 已验证曝光控制能写入，但最终仍要结合幅度、有效点和温度动态调节。

### 10.6 标定与补偿参数

| 参数                 | 含义                                               | 对效果的影响                                     |
|----------------------|----------------------------------------------------|--------------------------------------------------|
| EEPROM Calibration   | 模组出厂标定数据                                   | 深度解算必须匹配当前模组                         |
| Offset Calibration   | 距离零点偏差                                       | 影响绝对距离                                     |
| Wiggling Correction  | 相位非线性补偿                                     | 降低周期性距离误差                               |
| Temperature Compensation | 温度补偿                                       | 温度变化时保持距离稳定                           |
| Lens Calibration     | 内参/畸变标定                                      | 影响点云几何                                     |
| Bad Pixel Map        | 坏点表                                             | 过滤异常像素                                     |
| Crosstalk Correction | 串扰补偿                                           | 降低镜头/窗口内反射造成的近距离假点              |

ToF 模组常常高度依赖 EEPROM 标定。即使驱动能出图，如果 EEPROM 数据不匹配，可能出现距离偏差、平面弯曲、点云变形。

### 10.7 数据接口参数

| 参数                 | 含义                                               | 对效果的影响                                     |
|----------------------|----------------------------------------------------|--------------------------------------------------|
| MIPI Lanes           | MIPI 数据 lane 数                                  | 决定带宽                                         |
| MIPI Data Rate       | 单 lane 速率                                       | 速率不匹配会无帧或花帧                           |
| Pixel Format         | 例如 Y12                                           | 决定 raw phase 数据解释方式                       |
| Frame Height         | ToF 可能输出多相位复合帧，高度不是最终深度高度      | SDK 需要按序列拆分                               |
| Buffer Count         | V4L2 buffer 数量                                   | 影响连续取流稳定性                               |
| Timestamp            | 帧时间戳                                           | 多传感器同步和动态测量需要                       |
| Sequence             | 帧序号                                             | 判断丢帧和卡顿                                   |

ToF 传感器的 MIPI 输出可能不是普通单帧图像，而是多相位、多序列的复合帧。驱动必须把 media graph、格式、高度、buffer size 配对正确。

### 10.8 可靠性与安全参数

| 参数                 | 含义                                               | 对效果的影响                                     |
|----------------------|----------------------------------------------------|--------------------------------------------------|
| Illumination Temperature | 照明侧温度                                     | 过高会影响寿命和安全                             |
| Sensor Temperature   | 传感器温度                                         | 影响深度漂移                                     |
| NTC Temperature      | 模组热敏电阻温度                                   | 判断整体热状态                                   |
| Eye Safety           | 人眼安全等级                                       | VCSEL/激光类产品必须考虑                         |
| Thermal Throttle     | 热降额策略                                         | 温度高时降帧率、降功率、降曝光                   |
| Watchdog             | 取流或 SDK 卡死监控                                | 提高长期运行稳定性                               |

当前 C005 调试中已经看到照明温度可能升高，因此后续工程化必须加入温度保护。

## 12. ToF 与其他 3D 技术对比

| 技术         | 原理                         | 优点                         | 缺点                         | 适合场景                         |
|--------------|------------------------------|------------------------------|------------------------------|----------------------------------|
| ToF          | 主动光飞行时间/相位           | 实时、结构简单、直接出深度   | 受环境光、反射率、温度影响   | 中近距离实时深度                 |
| 双目         | 两个相机做视差匹配             | 不一定需要主动光             | 依赖纹理，弱纹理难匹配       | 户外、机器人、低成本             |
| 结构光       | 投射图案并解析变形             | 近距离精度高                 | 室外强光较难，结构复杂       | 人脸识别、近距离扫描             |
| LiDAR        | 激光扫描或阵列测距             | 远距离、精度高               | 成本高，点密度/体积受限      | 自动驾驶、测绘、远距离感知       |
| RGB + AI     | 单目深度估计                   | 硬件简单                     | 绝对距离不可靠               | 语义理解、低成本辅助             |

C005 这类 iToF 摄像头的优势是中近距离实时深度和点云，适合嵌入式 Web 可视化、空间交互、人体/物体距离感知等应用。

## 13. ToF 选型关注点

| 类别         | 关键问题                                             |

| 接口         | MIPI/USB/I2C/SPI？是否有 Linux V4L2 驱动？            |
| SDK          | 是否提供深度、幅度、点云、滤波、AE 接口？             |
| 环境光       | 室内/室外表现如何？强阳光下最大距离是多少？           |
| 材质         | 黑色、玻璃、金属、人体、纸板表现如何？                |
| 供电         | 传感器和照明分别需要什么电压和电流？                 |
| 散热         | 是否需要金属支架、导热垫或主动散热？                 |

## 15. 核心判断口诀

调 ToF 时不要只看一项参数，要联动看：

```text
Distance 看距离
Amplitude 看回波
ROI valid 看可信点数量
Exposure 看积分时间
Temperature 看热稳定
Point Cloud 看空间趋势
```

如果：

```text
Distance 有人影
Amplitude 有人影
ROI 均值随前后移动变化
点云随左右/前后移动同步变化
温度可控
```

则说明 ToF 驱动和基础解算链路已经基本打通。

如果要进入“精确三维建模”阶段，还需要：

```text
距离误差标定
平面拟合误差
点云导出
温度漂移测试
多距离多材质测试
```
