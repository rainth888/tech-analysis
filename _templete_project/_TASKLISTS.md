# 项目任务清单

## 使用规则

- 本文件只登记用户直接发布的任务，或为完成用户任务而必须拆解的更细子任务。
- Agent 不得根据历史建议、个人兴趣或推测自行增加任务。
- 新任务必须记录来源、范围、状态、优先级、依赖和完成标准。
- 必要子任务必须挂在原始用户任务下，不得扩大原始需求边界。
- `_STATE.md` 是紧凑并行看板；完整待办以本文件为准，各环境实时进度以 `.agents/parallel/lanes/` 中对应 lane 为准。
- 新任务在接收它的 lane 中成为最高优先级；除非用户明确指定，不得暂停或替换其他文件/资源不重叠的活跃 lane。
- Agent 完成实现和内部验证后，只能把任务标记为 `🧪 AWAITING_USER_CONFIRMATION`。收到用户明确的测试通过、稳定、完成或验收通过答复后，才可标记 `✅ COMPLETED` 并追加到 `_STATE_HISTORY.md`。
- 用户未明确答复、答复含糊或只发布了另一项新任务，均不视为验收通过；后续交付任务或会话中必须继续提醒一次，直到收到明确结果。
- 用户确认失败或提出问题时，任务恢复为 `🔄 IN_PROGRESS`；当前任务完成并获用户确认后，自动领取下一项符合条件的任务。
- 暂停、阻塞任务仍属于未完成任务，不得删除。用户可以调整优先级、暂停、取消或替换任务。
- 涉及 `_CHECKLISTS.md` 中 `🔒 STABLE` 功能时，必须遵守稳定功能冻结和修改授权规则。

## 状态定义

- `⏳ TODO`：尚未领取。
- `⏳ NEXT`：已选为下一任务。
- `🔄 IN_PROGRESS`：正在执行。
- `⏸️ PAUSED_BY_NEW_TASK`：仅当用户明确要求新任务替换或暂停该 lane 时使用。
- `⏸️ PAUSED`：等待用户、硬件或外部条件。
- `🧪 AWAITING_USER_CONFIRMATION`：实现和内部验证已结束，等待用户明确测试或验收结论。
- `❌ BLOCKED`：存在明确阻塞，当前无法继续。
- `✅ COMPLETED`：完成标准全部满足并已归档。
- `🚫 CANCELLED`：用户明确取消或任务被新需求替代。
