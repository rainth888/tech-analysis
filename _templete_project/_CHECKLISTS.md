# 项目功能清单

## 文档用途

本文档是项目功能、代码位置、交叉影响和开发状态的唯一登记入口。处理新需求、Bug、重构、调参或适配前必须先阅读本文档。

## 状态定义

- `🔒 STABLE`：开发人员完成测试并明确认定稳定；对应代码范围冻结。
- `✅ VERIFIED`：已有明确验证证据，但尚未获得稳定定案。
- `🔄 IN_PROGRESS`：正在开发、修复或重新验证。
- `🧪 TESTING`：实现已存在，正在测试或等待反馈。
- `🟡 IMPLEMENTED`：代码已实现，但尚无充分验收证据。
- `⏳ PLANNED`：需求已确定，尚未完整实现。
- `⛔ DISABLED`：正式版本明确禁用，仅保留兼容或诊断代码。
- `⚠️ CHANGE_APPROVED`：稳定功能修改已获用户明确批准，尚未完成重新验证。
- `🔄 REVALIDATING`：获准修改的稳定功能正在回归验证。

只有开发人员或用户明确宣布功能稳定后，才能标记 `🔒 STABLE`。不得把代码存在、编译通过、自动测试通过或 Agent 自行判断等同于稳定。

## 稳定功能修改流程

1. 开始任务前定位目标功能、代码范围和交叉影响。
2. 若目标或交叉功能为 `🔒 STABLE`，立即停止编辑并向用户提示。
3. 提示必须包含稳定功能名称、代码范围、修改必要性、影响面、回归方案和回退方案。
4. 只有用户明确允许后，才能改为 `⚠️ CHANGE_APPROVED` 或 `🔄 REVALIDATING` 并开始修改。
5. 修改后回归目标功能及全部交叉功能，并记录版本、环境、结果和证据。
6. 只有开发人员或用户再次明确认定稳定后，才能恢复为 `🔒 STABLE`。

## 功能清单

当前模板没有预设业务功能。项目初始化后，从 `F001` 开始登记，每项至少包含：

- 功能编号、名称和状态。
- 功能范围和明确边界。
- 对应代码、配置、脚本或资源位置。
- 上游依赖、下游消费者和交叉影响功能。
- 验证方法、最近结果和证据路径。
- 最后更新时间；若为稳定功能，还要登记稳定版本和冻结代码范围。

## 稳定功能登记

当前无稳定功能。后续每项稳定登记必须包含功能编号、稳定版本或提交、测试人员、日期、环境、测试范围、证据路径和冻结代码范围。

## 变更批准记录

当前无稳定功能变更批准记录。获准修改稳定功能时，必须登记批准人、时间、原因、范围、交叉影响、回归计划、回退方案和最终复验结论。
